# CircuitPro RP 1.x / ProtoLaser U4 Manufacturing Input

Read this reference when preparing or diagnosing KiCad manufacturing inputs for an LPKF ProtoLaser U4 running CircuitPro RP 1.x.

## Separate parser format from manufacturing target

CircuitPro's import screen makes two independent decisions for every selected file:

1. `Format` chooses the parser used to decode the file.
2. `Target` assigns the decoded geometry to a manufacturing layer or operation.

A file can preview at the correct size while still be unusable by the workflow if its target remains a filename-named user layer. Set both fields explicitly.

| KiCad content | File extension | CircuitPro `Format` | CircuitPro `Target` |
| --- | --- | --- | --- |
| Front copper | `.gtl` | `GerberX` | `TopLayer` |
| Back copper | `.gbl` | `GerberX` | `BottomLayer` |
| Finished outer perimeter | `.gm1` | `GerberX` | `BoardOutline` |
| Electrical through-hole or via drill | `.drl` | `Excellon` | `DrillPlated` |
| Mechanical-only non-plated drill | `.drl` | `Excellon` | `DrillUnplated` |

Do not leave `Target` on an imported name such as `Top.gtl`, `Profile.gm1`, or `Drill_1mm.drl`; those are unclassified user layers. Use `CutInside` only for a deliberate internal cutout, not the finished perimeter. Do not manually mirror back copper; the double-sided CircuitPro workflow owns the material turn and registration transform.

## Why these formats

- Choose `GerberX` (RS-274X) for copper and profile. It embeds aperture definitions, is directly generated by KiCad, and gives older CircuitPro a small geometry-focused input.
- Do not choose legacy `Gerber` (RS-274-D): it depends on a separate aperture table and adds an avoidable mismatch risk.
- Do not choose `GerberX2` for RP 1.x compatibility. KiCad's X2 object and net attributes are not needed for U4 geometry, and the installed RP 1.0 system has reported them as ignored.
- Choose `Excellon` for drilling. It preserves tool diameters and drill coordinates independently from copper geometry and is produced directly by KiCad.
- Do not substitute DXF for normal copper or drill data. DXF is useful for geometry interchange but loses the direct PCB layer and drill-tool contract and increases manual classification.
- Do not substitute ODB++, IPC, JOB, LMD, or S&M merely because CircuitPro lists them. They add no benefit to this narrow KiCad-to-RP-1.x workflow, may require another producer or configuration, and have not been validated against the installed system.

LPKF's published CircuitPro feature list confirms GerberX and Excellon as supported import formats. The exact RP 1.0 target labels above are installation-level evidence from the working import UI and must be rechecked if the software version changes.

## KiCad export contract

Before using a helper or CLI fallback, load the current Konnect `pcb_export` and `manufacturing` schemas. Use native guarded export tools when they expose every required option. The currently verified manufacturing-package tool targets board houses, and the current `export_gerber` surface does not expose the RP 1.x compatibility switches; for that proven gap, use KiCad CLI.

Gerber requirements:

- export only the copper sides actually used plus `Edge.Cuts`;
- retain Protel extensions;
- disable X2 attributes with `--no-x2`;
- disable netlist attributes with `--no-netlist`;
- keep one absolute coordinate system shared with the drill output.

Excellon requirements:

- millimetres;
- absolute origin;
- explicit decimal coordinates;
- Y mirroring disabled;
- full header, not minimal header;
- PTH and NPTH separated;
- normal routed representation for oval holes unless the installed process requires otherwise.

In decimal mode, a displayed drill-artwork size such as `1 x 1 mm` is the geometric extent of one 1 mm hole. It is not evidence of a `1:1` integer/fraction coordinate format; KiCad's precision control is not used to reinterpret explicit decimal coordinates.

## Filename and directory contract

Use a separate machine-input directory for each independently imported board or variant. The directory name identifies the design or variant, so filenames inside it can remain short, ASCII-only, and role-based.

Preferred names:

- `Top.gtl`
- `Bottom.gbl`
- `Profile.gm1`
- `Drill_PTH.drl` for a general electrical drill file
- `Drill_NPTH.drl` for a non-empty mechanical drill file

A dimension-specific name such as `Drill_1mm.drl` is acceptable only when the file is proven to contain exactly that one tool size. If more sizes are introduced, rename by role rather than preserving a false dimension claim.

The extensions are the conventional Protel/KiCad role hints; the basename is for operator clarity. Never depend on the filename alone for manufacturing behavior: verify the CircuitPro `Target` explicitly.

The directory selected for import must contain only actual machine inputs. Exclude ZIP archives, Gerber job files, empty drill files, documentation, maps, reports, logs, and earlier export attempts. CircuitPro RP 1.x may try to classify every selected file and report failures for harmless metadata or empty outputs.

## PTH meaning in a no-THP process

Classify holes by electrical design intent, not by whether this fabrication run plates the barrel. A CAD via that will be manually solder-filled between front and back copper remains logical PTH data and maps to `DrillPlated`. Selecting a `U4_DoubleSided_NoTHP` workflow suppresses the plating process; it does not turn the connection into a mechanical NPTH. Document the manual solder operation and require a front-to-back continuity test.

## Delivery validation

Before delivery:

1. preserve any previous delivered package in a recoverable operating-system temporary backup;
2. prove the source board is the intended saved revision and run the appropriate DRC;
3. confirm each import directory contains only intended, non-empty machine inputs;
4. reject Gerbers containing X2 object/net attributes such as `TO,N,...`;
5. confirm each drill file contains at least one tool and coordinate;
6. confirm copper, drill hits, and profile use the same absolute origin and intended overlay;
7. record the expected displayed extents, noting that profile display bounds may include the Gerber drawing aperture while the cut follows its centerline;
8. in CircuitPro, verify every `Format` and `Target`, preview the overlay, add the workflow's registration features outside the finished profile, process both copper sides before cutting the profile, and accept the result only after a physical coupon when the material/process combination is new.

Future automation should wrap the verified KiCad CLI calls, normalize filenames by role, omit empty drill outputs, and fail on unexpected files or attributes. It must not silently overwrite a prior package, infer PTH/NPTH from the no-THP workflow name, or declare fabrication readiness without DRC, overlay review, and a process coupon.
